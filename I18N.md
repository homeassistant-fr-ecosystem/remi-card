# I18N — Guidelines de traduction (Rémi Card)

Ce document détaille la procédure pour ajouter ou améliorer une traduction de la carte Rémi.

## Langues supportées

Actuellement : **anglais (`en`)** et **français (`fr`)**.

Les fichiers de traduction se trouvent dans `src/translations/` :
- `en.json` — anglais (langue de référence)
- `fr.json` — français

## Ajouter une nouvelle langue

### 1. Créer le fichier de traduction

Copiez le fichier de référence anglais :

```bash
cp src/translations/en.json src/translations/XX.json
```

Remplacez `XX` par le code de langue cible (ex: `es`, `de`, `it`).

### 2. Traduire toutes les chaînes

Traduisez chaque valeur du fichier. Consultez la section [Qualité de traduction](#qualité-de-traduction) ci-dessous.

### 3. Enregistrer la langue dans `src/localize.ts`

Ajoutez l'import et l'entrée dans la table `LANGUAGES` :

```typescript
import * as XX from './translations/XX.json';

const LANGUAGES: Record<string, Record<string, unknown>> = {
  en,
  fr,
  XX, // Ajoutez ici
};
```

### 4. Construire et tester

```bash
npm run build
npm run test
npm run lint
```

### 5. Ouvrir une PR

Soumettez votre traduction via une pull request sur GitHub.

## Améliorer une traduction existante

1. Éditez le fichier approprié dans `src/translations/`
2. Assurez-vous que toutes les clés sont présentes (voir vérification ci-dessous)
3. Testez dans Home Assistant
4. Soumettez une PR

## Structure des clés

Les clés utilisent la notation pointée (`"section.face_selector"`). Certains noms de clés contiennent eux-mêmes des points (ex: `"section.face_selector"` est une clé plate, pas un objet imbriqué). Ne modifiez pas les clés — seules les valeurs doivent être traduites.

Les sections principales :
- `common` — chaînes génériques (on/off, inconnu, Rémi)
- `face` — noms des visages (sleepy, awake, semi-awake, smily, blank)
- `face_selector` — titre de la section
- `light_controls` — titre de la section veilleuse
- `connectivity` — statut WiFi
- `firmware` — version et mise à jour du firmware
- `device_info` — informations appareil
- `settings` — réglages appareil
- `clock_format` — format 12h / 24h
- `music_mode` — mode musique / bruit blanc
- `temperature` — température et historique
- `alarm` — réveils (titre, ajout, suppression, test, snooze, jours)
- `error` — message d'erreur absence d'entités
- `editor` — libellés de l'éditeur de configuration

## Qualité de traduction

Checklist avant soumission :

- [ ] Traduction fidèle au sens original
- [ ] Phrasage naturel dans la langue cible
- [ ] Niveau de formalité approprié
- [ ] Terminologie cohérente avec les autres chaînes
- [ ] Pas de troncature ou de débordement dans l'interface
- [ ] Adaptation culturelle si nécessaire

## Vérification automatique

Un test unitaire (`src/remi-card.test.ts`, suite `i18n key consistency`) vérifie à chaque build que :

1. `en.json` et `fr.json` partagent les mêmes clés de premier niveau
2. Toutes les clés feuilles (récursif) sont identiques entre les deux fichiers
3. Toute valeur de traduction est une chaîne non vide

Si vous ajoutez une nouvelle langue, le test ne l'inclut pas encore (il compare seulement `en` et `fr`). Pensez à faire vérifier manuellement que votre fichier contient toutes les clés présentes dans `en.json`.

## Exemple de clé

```json
{
  "common": {
    "on": "Allumé",
    "off": "Éteint"
  },
  "face": {
    "sleepy_face": "Sommeil",
    "awake_face": "Éveil"
  }
}
```
